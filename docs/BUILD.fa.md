# بازتولید خروجی‌های یاسی

منبع تألیفی اصلی، فایل‌های JSON در `volumes/12`، `volumes/13` و `volumes/14` است. پاسخ‌ها، ترتیب گزینه‌ها، منابع خوانده‌شده و مشخصات گره/یال شکل‌ها در این فایل‌ها قابل ویرایش‌اند. HTML، PDF و DOCX خروجی تولیدشده‌اند؛ اصلاح علمی را ابتدا در منبع ثبت کنید.

## محیط

- Python 3.12 و وابستگی‌های نسخه‌بندی‌شده `tools/requirements.txt`.
- Chromium در `/usr/bin/chromium` و Graphviz (`dot`)؛ فونت Noto Naskh Arabic برای Pango/Graphviz نصب باشد. فایل فونت و مجوز آن در `assets/fonts` است.
- فونت متن PDF و Word، Noto Naskh Arabic چهارده پوینت است؛ تصویر جلد با B Nazanin ساخته شده است. انتخاب فونت متن با گزینه مجاز «Noto یا فونت فارسی مشابه خوانا» در مکالمه ورودی سازگار است.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r tools/requirements.txt
python -m unittest discover -s tools -p 'test_*.py'
python tools/validate_books.py
python tools/build_books.py 12 13 14
python tools/qa_outputs.py
```

نسخه PyMuPDF را رعایت کنید: ۱٫۲۶٫۶ در استخراج بعضی صفحات راست‌به‌چپ این پروژه خطای بومی segmentation fault داشت. نسخه ۱٫۲۸٫۲، متن و هندسه همه صفحات را خوانده و رندر کرده است. تغییر فونت به‌تنهایی این خطای ابزار را به‌طور قابل اتکا رفع نکرد؛ به همین دلیل بررسی نهایی با نسخه جدید انجام شد.

ابزار ساخت یک HTTP server موقت روی loopback برای Chromium باز می‌کند و به اینترنت وابسته نیست. خط‌مشی محیط فعلی، بازکردن مستقیم `file://` را مجاز نمی‌کرد؛ خواندن فایل‌های خود پروژه از HTTP محلی پشتیبانی می‌شود. پس از پایان ساخت، سرور بسته می‌شود.

## آزمون‌ها و خروجی‌ها

`validate_books.py` تعداد فصل/گام/سؤال، چهارگزینه‌ای‌بودن، ارجاع‌ها، شناسه‌ها، وجود شاهد تصویری سنوات و پوشش دو رشته را کنترل می‌کند. این کنترل، داوری علمی نیست. `qa_outputs.py` همه صفحات PDF را رندر می‌کند و متن بیرون کاغذ، صفحه خالی، کاراکتر جایگزین، گم‌شدن سؤال در Word، هندسه SVG و پیوندهای واقعی داخلی PDF را کنترل می‌کند.

پیوندهای نام‌دار Chromium هنگام ادغام با `insert_pdf` منتقل نمی‌شدند؛ ابزار ساخت آنها را به پیوند صفحه‌ای با offset جلد و تبدیل دستگاه مختصات تبدیل می‌کند. صرف وجود outline برای تأیید فهرست پیونددار کافی نیست.

شیت‌های بازبینی و نمونه‌های بزرگ در `work/qa` ساخته می‌شوند و وارد Git نمی‌شوند. نتیجه ماشینی و گزارش‌های انسانی در `docs/qa` ثبت می‌شوند. گزارش‌های قدیمی، SHA نسخه بررسی‌شده را دارند؛ وضعیت پس از اصلاح جدا ثبت می‌شود.

DOCX متن، سؤال‌ها، پاسخ‌ها، جدول‌ها و فهرست پیونددار را قابل ویرایش نگه می‌دارد؛ جلدها و شکل‌ها تصویرند. همه سؤال‌ها با منبع مقایسه ماشینی شده‌اند. صفحه‌بندی Word ممکن است بسته به نسخه نرم‌افزار و فونت نصب‌شده تغییر کند؛ PDF مرجع صفحه‌آرایی بررسی‌شده است. در این محیط رندر خود Word انجام نشده است.

`rebalance_exams.py` پیش از ساخت، صد سؤال مستقل هر جلد آموزشی را به چهار آزمون ۲۵سؤالی بازچینی کرده است؛ هر آزمون هر ده فصل را پوشش می‌دهد. `origin_id` شناسه خاستگاه را حفظ می‌کند. بازچینی دوباره لازم نیست مگر بانک آزمون تغییر کند.
